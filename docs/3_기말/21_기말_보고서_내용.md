# 기말 보고서 내용 정리 (초안, 2026.11.20 · 11.27 갱신)

한글(.hwpx) 기말 보고서에 들어갈 내용을 장별로 정리한 것. 승인되면 이 내용으로 한글 파일을 만든다. 교수님의 기말 목차 안내를 따로 받지 못해 중간 보고서의 5장 구성을 뼈대로 하고, 중간 뒤에 한 일(전략 분석, 검증 결과, 피드백 반영)을 장으로 더했다. 안내가 오면 장 순서만 맞춘다.

- 문체: 개조식(~함, ~음, 명사로 끝냄). 인용은 그대로
- 【채울 것】은 아직 결과가 없는 자리. 숫자와 캡처만 넣으면 되게 문장은 써 둠
- 숫자 출처는 맨 아래 부록 A

## 요약 (1쪽)

- **아이템**: 시급제 알바 대학생이 혼자 근무를 기록하고, 받았어야 할 돈과 실제 받은 돈을 비교해 덜 받은 금액을 찾고, 사장님께 보낼 요청 문구와 증빙 자료까지 만드는 모바일 웹앱
- **중간 발표 때**: 포함 기능 8개가 동작하는 앱을 배포, 설문 13명 응답, 인터뷰는 계획 단계
- **중간 뒤에 한 일**
  - 전략: BM 고도화, PEST, SWOT, STP, 4P 분석과 포지셔닝 맵으로 타깃·수익 모델·알리는 방법을 다시 잡음
  - 검증: 설문 15명【최종 N명】, 카톡 인터뷰 3명(계획 5명 중 3명)
  - 개발: 확인 페이지에서 기록 내용과 확인 번호를 맞춰 보는 기능(중간 때 약속), 기록 등록 설명을 쉽게 고침, 요청 메시지를 짧게 묻기·자세히로 고르고 메시지 앱으로 바로 보내게 함
  - 피드백 반영: 중간 발표에서 받은 의견 4가지를 검토해 2가지 반영, 2가지는 이유를 붙여 하지 않음
- **검증에서 알게 된 것**
  - 맞았던 것: 급여를 따져 보지 않는 사람이 많음(설문 알바 경험자 13명 중 8명이 통장 총액만 봄, 인터뷰 3명 모두 같음), 가장 쓸모 있는 기능은 "받은 돈과 비교"(15명 중 8명)
  - 틀렸거나 약했던 것: 게임은 안 쓸 기능 1위(15명 중 8명), 차별점으로 내세운 기록 등록은 가장 쓸모 있다고 꼽은 사람 0명
  - 그래서 바꾼 것: 비교를 앞세우고, 기록 등록은 설명부터 쉽게, 게임은 설정에서 숨길 수 있는 보조 기능으로만 두고 광고 수익은 가설로 남김
- **수익**: 핵심 화면은 무료·광고 없음. 1차 게임 화면 광고(가설), 2차 편의 기능 구독, 3차 기관 연계. 문서 유료화·찾은 돈 수수료는 하지 않음
- **한계**: 설문·인터뷰 대상이 지인 중심이고 수가 적음. 실제 급여일을 거친 사용 기록은 아직 없음

## 2. 창업 아이템 정의 및 필요성

**2.1 배경 및 문제점** (중간 보고서와 같은 세 가지, 근거를 최신으로)

문제 1. 얼마를 받아야 하는지 계산하기 어려움
- 주휴수당(주 15시간 이상 + 개근), 야간수당(22~06시, 5인 이상)은 조건이 있어 스스로 판단하기 어려움
- 노동절에 일한 알바생 중 수당을 받는다는 응답 38.5%, "안내받지 못해 모르겠다" 33.2% (알바천국 2026.4, 749명)
- 우리 설문: 급여를 받을 때 "내 계산이 맞는지"가 걱정 15명 중 8명

문제 2. 덜 받아도 알아채기 어려움
- 우리 설문: 알바 경험자 13명 중 8명이 통장 총액만 봄. 인터뷰 3명 모두 "통장에 꽂히는 것만", "알람으로", "잘 안 함"
- 최저시급보다 적게 받은 경험 31.9%, 그중 49.0%는 근로계약서를 쓰지 않음 (알바천국 2026.6, 1,804명)
- 임금 문제 중 가장 많은 유형은 주휴수당 등 수당 미지급·지연 37.3% (알바천국 2025.1, 2,457명)

문제 3. 알아도 말을 꺼내기 어려움
- 최저시급 미달 경험자 중 49.3%가 아무 대응도 하지 않음, 노동부 신고 등 공식 절차는 9.9% (알바천국 2026.6)
- 우리 설문: 사장님과의 관계가 걱정 15명 중 6명. 인터뷰 1명은 요청 메시지를 "보낼 수는 없을 것"이라고 답함
- 신고 창구는 있지만 그 앞 단계(확인 → 비교 → 요청)가 비어 있음

**2.2 해결 방안**: 근무 기록 → 급여 비교 → 정산 요청을 앱 하나로 이음
1. 수정 이력이 남는 근무 기록: 출근·퇴근 버튼. 고치면 전후 시각·시점·사유가 남고, 삭제도 흔적이 남음
2. 입금액 비교: 기본급 + 주휴수당 + 야간수당으로 받았어야 할 돈을 계산하고 실제 받은 돈과 비교
3. 단계별 정산 요청: 정중한 메시지 → 내용증명 초안 → 진정 절차 안내(1350·노동포털 연결)
4. 증빙 묶음 PDF와 기록 등록: 기록·수정 이력·계산 근거·입금 내역·사진을 한 문서로. 기록마다 확인 번호와 서버 등록 시각

설계 원칙 (중간과 같음)
- 사장 연동 없음, 로그인 없음, 근무 내용은 폰 안에만
- 문서의 효력을 장담하지 않음. 판단은 근로감독관·법원이 하고, 앱은 판단할 자료를 정리함
- 진정서는 만들지 않음. 신고 창구로 연결까지만

**2.3 핵심 타깃 고객** (STP에서 다시 잡음, 4.3 참고)
- 급여를 어디까지 확인하느냐로 넷으로 나눔: A 총액만 봄 / B 기록·계산만 해 봄 / C 알지만 말 못 함 / D 신고까지 감
- 타깃: A 중 주 15시간 이상 일하는 만 19~26세 시급제 대학생 알바(카페·편의점·음식점)
- 고른 이유: 확인한 경쟁 앱은 B까지만 도움. 주 15시간 이상이면 놓칠 수 있는 돈이 큼(주휴수당만 4주 123,840원, 2026년 최저임금 기준)

| 만든 요청 문구를 실제로 보낼 수 있음 | 5명 중 3명 "보내겠다" | 3명 중 2명(1명은 고쳐서), 1명은 "보낼 수는 없을 것" | 방향은 맞음. 짧게 묻는 문구를 기본으로 하고 고쳐서 바로 보내게 고침(11/20) |
| 확인 번호 설명을 이해함 | 5명 중 4명 | 3명 중 2명이 설명이 필요하다고 함, 설문 쓸모 1위 0명 | 못 미침. 설정·증빙 설명을 쉽게 고침(11/20) |
| 타깃 중 주 15시간 이상이 다수 | 30명 이상, 알바 중인 응답자의 반 이상 | 【설문 최종 숫자】 응답 수가 기준에 못 미침 | 판단 보류. 주휴수당 중심 메시지는 유지하되 근거는 공개 통계로 |
| 게임 화면 광고를 받아들임 | "싫다"가 반 미만 | 설문 "싫다" 15명 중 5명, 인터뷰 3명 중 2명 부정, 안 쓸 기능 1위 | 설문 기준만 보면 넘었지만 인터뷰와 "안 쓸 기능 1위"가 반대 방향. 실제 광고로 확인하지 못해 판단 보류. 게임은 숨길 수 있는 보조 기능으로 유지, 광고 수익은 가설로 둠 |

- 기준은 5명을 놓고 정했는데 인터뷰는 3명이라, 판정이 아니라 방향으로만 읽음

**6.5 검증으로 바뀐 것**
- 그대로: 급여를 따져 보지 않는 사람이 많음 → 비교를 맨 앞에
- 약점이 커진 것: 게임 화면 광고 → 수익의 중심으로 보지 않음. 게임은 보조 기능으로만 두고, 첫 화면에서는 돈 알림 아래에 둠(설정에서 숨길 수 있음)
- 다시 본 것: 기록 등록 → 설명을 쉽게, 내용과 맞춰 보는 기능으로 "무엇을 확인해 주는지"를 눈에 보이게
- 다시 본 것: 요청 메시지 → 처음 꺼내는 말은 짧게(차액과 확인 부탁만), 근거는 물어보면 보내는 순서로
