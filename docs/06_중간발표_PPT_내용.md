## ② 문제 정의 (2장)

**3장 타겟과 페인 포인트**
- 타겟: 주 15시간 이상 일하는 만 19~26세 시급제 알바 대학생 (카페·편의점·음식점)
- 세 가지 문제 (린 캔버스와 같은 순서)
  1. 얼마를 받아야 하는지 계산하기 어렵다. 주휴·야간수당 기준을 모름. 노동절 근무 알바생 33.2%가 "수당 받는지 안내받지 못해 모르겠다" (알바천국, 749명, 2026.4)
  2. 덜 받아도 알아채기 어렵다. 통장 총액만 보고 넘어감. 알바생 48.0%가 임금 관련 문제를 겪었고, 가장 많은 유형이 주휴수당 등 수당 미지급·지연 37.3% (알바천국, 2,457명, 2025.1)
  3. 알아도 말을 꺼내기 어렵다. 계약서·기록이 없음. 최저시급 미달 경험자 중 49.3%가 아무 대응도 안 함, 49%는 계약서를 안 씀 (알바천국, 1,804명, 2026.6)

**4장 기존 해결책의 한계** (표 하나)
| 서비스 | 하는 것 | 못 하는 것 |
|---|---|---|
| 하우머치 | 혼자 기록, 예상 급여 계산 | 실제 입금액과 비교, 덜 받았을 때 대응 |
| 기그 | 출퇴근 기록, 전자 근로계약서 | 사장과 연결해야 작동. 소규모 매장은 연결이 안 됨 |
| 알바천국·알바몬 계산기 | 일회성 계산 | 기록이 남지 않음 |
| 진정24·노동포털 | 진정서 작성, 접수 | 증거를 이미 갖춘 사람만 쓸 수 있음 |
- 한 줄 결론: "얼마 받아야 하나"까지는 있는데, "덜 받았으면 어떻게 받아내나"는 비어 있다

## ③ 솔루션 · 핵심 가치 (2장)

**5장 서비스 개요: 기록 → 비교 → 요청**
- 기록: 출근·퇴근 버튼. 고치면 수정 전·후와 사유가 남는다
- 비교: 주휴·야간수당까지 계산한 "받았어야 할 돈"과 "실제 받은 돈"의 차액
- 요청: 사장님께 보낼 정중한 메시지 → 내용증명 초안 → 진정 절차 안내(1350·노동포털 연결)
- 신고 창구를 새로 만드는 게 아니라, 신고 이전 단계를 채운다
- (첫 화면·급여 비교·정산 요청 캡처 3장)

**6장 차별화 포인트**
- 사장 연동 없이 혼자 쓴다
- 실제 입금액과 비교해 차액을 찾는 앱은 아직 없다
- 기록 등록: 기록할 때마다 서버에 확인 번호와 등록 시각이 남아, "그때 기록한 그대로"를 제3자가 확인할 수 있다 (비교한 네 서비스 모두 없음)
- 약점도 먼저 말한다: 비교 기능은 경쟁 앱이 입력 칸 하나로 따라올 수 있다. 그래서 기록의 신뢰성(확인 번호)을 키우는 쪽으로 간다

## ④ SW 기술 아키텍처 · 핵심 기능 (2장)

**7장 기술 스택** (표)
| 구분 | 선택 | 이유 |
|---|---|---|
| 프론트엔드 | React + Vite, PWA(홈 화면에 추가해 앱처럼) | 스토어 없이 링크로 배포, 바로 고쳐서 다시 배포 |
| 백엔드 | 서버 없음 + Supabase REST | 근무 내용은 폰 밖으로 안 나감. 서버는 확인 번호 등록에만 |
| 데이터베이스 | 폰: localStorage·IndexedDB / 서버: Supabase PostgreSQL | 기록은 폰에, 서버에는 확인 번호·등록 시각만 |
| 인프라 | GitHub Pages + GitHub Actions | main에 올리면 자동 배포 |
| AI | 선택 사항(Claude API, 개발 환경에서만) | 배포 앱은 API 키 없이 기본 문구로 동작 |
| 분석 | 설문 페이지(Supabase) + 인터뷰 | 로그인이 없어 사용 로그 대신 설문으로 |

**8장 시스템 구성도 · 데이터 흐름도** (그림 1장, 새로 그린다)
- 폰(PWA): 화면 ↔ localStorage(기록)·IndexedDB(사진) ↔ 계산(급여·비교·문구·PDF)
- 폰 → Supabase: 기록 내용의 확인 번호(SHA-256 앞 16자)·기록 번호·무작위 폰 번호만 → 서버 시각으로 저장(수정·삭제 불가)
- 누구나 → 확인 페이지(verify.html) → Supabase에서 등록 시각 조회
- GitHub main → Actions → Pages 배포
- 그림에 "근무지·시각·금액은 서버로 가지 않음" 표시

## ⑤ 개발 현황 · MVP 시연 (3장 + 시연)

**9장 구현된 기능과 계획 대비 비율**
- 한 줄: MVP 계획 기능 8개가 모두 동작하는 수준으로 구현해 배포했고, 실제 사용자 검증은 아직
- 표 (100%는 쓰지 않고 남은 일을 같이 적는다)
| 기능 | 상태 | 남은 일 |
|---|---|---|
| 근무 기록(수정 이력·퇴근 누락 보호) | 90% | 실제 폰에서 장기 사용 확인 |
| 캘린더(예정 vs 실제, 연장·대타) | 85% | 반복 스케줄 입력 편의 |
| 급여 계산(주휴·야간·최저임금 표) | 85% | 연장근로 가산 미반영 |
| 입금액 비교·차액 알림 | 80% | 입금 문자·명세서 사진 자동 인식(보류) |
| 단계별 정산 요청 | 75% | 문구 톤 사용자 검증, AI 문구는 선택 |
| 증빙 묶음 PDF | 80% | 실제 폰 PDF 저장 확인 |
| 기록 등록(확인 번호) | 70% | 제3자가 내용으로 번호를 다시 계산하는 방법 |
| 기록 백업 | 80% | 실제 폰 파일 저장 확인 |
- 계획 대비 구현 비율: 기능 수로 8/8, 완성도 평균 약 80%

**10장 UI 화면** (캡처 4~6장: 첫 화면, 캘린더, 급여 비교, 정산 요청, 증빙 PDF, 확인 페이지)
- 디자인 방향: 통장처럼 "일하면 돈이 쌓인다"가 보이게. 잉크 남색 = 기록을 잉크로 남긴다

**11장 시연 순서** (실제 앱, 인터넷 안 되면 캡처·녹화)
1. 설정 → 예시 데이터 넣기
2. 출근·퇴근 → 설정에서 "2건 등록됨"
3. 캘린더에서 연장·대타
4. 첫 화면 "9월 급여 받으셨나요?" → 받은 금액 입력 → 덜 받은 돈
5. 요청 메시지 생성(3개월 합계) → 증빙 묶음 PDF 7번 "기록 등록 확인"
6. 확인 페이지에 확인 번호 입력 → 등록 시각
7. 3단계 진정 안내(1350·노동포털)
- 전날 할 일: 앱에서 기록 하나 남겨 Supabase 깨우기

## ⑥ 시장 분석 · 비즈니스 모델 (3장)

**12장 시장 규모**
- 문제의 크기: 임금체불액 2023년 1조 7,845억 → 2024년 2조 448억 → 2025년 2조 679억 원, 2025년 피해 노동자 26만 2,304명 (고용노동부 임금체불 통계현황)
- 어디서: 30인 미만 사업장이 체불액의 67.8% (카페·편의점·음식점이 여기에 집중)
- 누가: 알바생 48.0%가 임금 문제 경험 (알바천국 2025.1). 대학생 아르바이트 경험률은 조사마다 67~88% (학교 단위 소규모 조사, 대표값 아님)
- 타겟 규모(어림): 고등교육기관 재적학생 307만 명(2026 교육기본통계, 교육부 2026.8.26) × 알바 경험률 약 70~80%(학교 단위 조사, 대표값 아님) → 약 200만 명 안팎이 알바 경험. 그중 주 15시간 이상 비율은 설문으로 파악
- 타이밍: 2025.9 정부 임금체불 근절 대책, 2025.10.23 개정 근로기준법 시행(상습 체불 제재). 증거만 있으면 돌려받는 길이 넓어졌다

**13장 경쟁사와 포지션** (2×2 그림)
- 가로축: 혼자 쓴다 ↔ 사장과 함께 / 세로축: 계산까지 ↔ 대응까지
- 하우머치(혼자·계산), 기그(함께·기록), 계산기(혼자·일회성), 진정24(대응·증거 있어야), 알바가드(혼자·대응까지)

**14장 비즈니스 모델 · 유저 확보**
- 핵심 화면은 무료·광고 없음
- 1차(가설): 게임 화면에만 광고. 웹에서도 보상형 광고 가능(Google H5 Games Ads, 승인 필요)
- 2차(후보): 여러 폰 동기화·자동 백업 같은 편의 기능 구독
- 하지 않는 것: 정산 문구·내용증명·증빙 묶음 유료화 (돈 받고 문서를 만들어 주면 변호사법·노무사법 문제에 가까워짐)
- 유저 확보: 대학 커뮤니티·에브리타임, 주휴수당 계산법 같은 짧은 영상, 학과·동아리 단톡. 설치가 아니라 링크라 전파가 쉽다
- 지표(앞으로): 설치(홈 화면 추가) → 첫 기록 → 한 달 뒤 받은 금액 입력 → 차액 발견 → 요청 보냄

## 예상 질문과 답 (발표자 메모, 슬라이드에는 안 넣음)

- "법적 효력 있나?" → 보장하지 않는다. 판단은 감독관·법원. 우리는 판단할 자료를 정리하고, 수정 이력과 확인 번호로 "나중에 고친 게 아니다"까지 보여 준다. 통장 내역·카톡과 함께 내야 한다고 앱에도 적어 뒀다
- "본인이 쓴 기록을 믿을 수 있나?" → 거짓 기록은 막을 수 없다고 인정. 막는 건 "나중에 고쳐 쓰기". 영세 사업장은 기록이 없는 경우가 많아 알바생 기록이 거의 유일한 자료가 되기 쉽다. 사장에게는 임금대장·계약 서류 보존 의무가 있다(근로기준법 48·42조)
- "하우머치가 따라 하면?" → 비교 기능은 따라올 수 있다. 그래서 확인 번호(기록 신뢰성)와 단계별 요청·증빙 묶음을 하나로 잇는 흐름이 차별점
- "법률 서비스 아닌가?" → 무료, 본인 기록을 정해진 양식에 채울 뿐, 개별 사안 검토·대행 없음, 진정은 1350·노동포털로 연결만
- "수익은?" → 게임 화면 광고(가설), 문서 유료화는 안 한다
- "팀원은 뭘 했나?" → 지금까지는 이지훈이 개발. 앞으로 시장·설문(손유호), 인터뷰·검증·일정(박명진)을 맡는다 (솔직하게)
