## 1. 프로젝트 개요

**1.1 프로젝트명**
알바가드 (못 받은 알바비, 기록으로 찾는 앱)

**1.2 팀명 및 팀원**
- 팀명: 알바가드 (앱 이름과 같게 정함)
- 팀장 이지훈 (컴퓨터소프트웨어 22학번): 기획, 개발, 배포, 문서 작성
- 팀원 손유호 (컴퓨터소프트웨어 [학번]): 시장·경쟁사 조사, 비즈니스 모델, 설문 집계 (10/27 이후)

시급제 아르바이트 대학생이 사장 연동 없이 혼자 출퇴근을 기록하고, 그 기록으로 계산한 급여와 실제 입금액을 비교해 덜 받은 돈을 찾고, 사장님께 보낼 정산 요청 문구와 증빙 자료까지 만들어 주는 모바일 웹앱.

## 2. 창업 아이템 정의 및 필요성

**2.1 배경 및 문제점**

문제 1. 얼마를 받아야 하는지 계산하기 어렵다
- 주휴수당(주 15시간 이상 + 개근), 야간수당(22~06시, 5인 이상 사업장)은 조건이 있어 알바생이 스스로 판단하기 어렵다
- 노동절 근무 알바생 중 수당을 받는다는 응답은 38.5%, "안내받지 못해 모르겠다"가 33.2% (알바천국, 749명, 2026.4)
- 급여 계산기는 여러 곳에 있지만, 넣을 근무 기록이 남아 있지 않아 실제로는 쓰이지 못한다

문제 2. 덜 받아도 알아채기 어렵고, 증명할 수단이 없다
- 통장에 들어온 총액만 보고 넘어간다
- 알바생 2,457명 중 48.0%가 임금 관련 문제를 겪었고, 가장 많은 유형이 주휴수당 등 수당 미지급·지연 37.3%, 전체 임금 지연·미지급 32.8%, 약속보다 적게 지급 23.9% (알바천국, 2025.1)
- 최저시급 미달 경험자의 49%가 근로계약서를 아예 쓰지 않았다 (알바천국, 1,804명, 2026.6). 시급이 얼마로 약속됐는지 증명할 문서가 없다

문제 3. 알아도 말을 꺼내기 어렵다
- 최저시급 미달 경험자 중 49.3%가 아무 대응도 하지 않았고, 사장과 직접 협의 27.1%, 신고 등 공식 절차 9.9% (알바천국, 2026.6)
- 관계가 불편해질 걱정, 금액이 작다는 이유, 근거가 없다는 점이 겹친다
- 신고 창구가 없어서가 아니라, 말을 꺼낼 근거와 시점이 마땅치 않아 문제가 덮인다

**2.2 해결 방안 (SW 솔루션)**

기록 → 비교 → 요청의 세 단계를 앱 하나로 잇는다.
1. 수정 이력이 남는 근무 기록: 출근·퇴근 버튼 하나. 기록을 고치면 수정 전·후 시각, 수정 시점, 사유가 함께 남고, 삭제도 "삭제됨"으로 표시만 한다. 퇴근 버튼을 12시간 넘게 안 누르면 끝난 시각을 묻는다. 캘린더에서 예정 스케줄과 실제 근무를 비교해 연장·대타·단축을 표시한다
2. 입금액 비교·차액 표시: 기본급 + 주휴수당 + 야간수당으로 "받았어야 할 돈"을 계산하고, 사용자가 넣은 "실제 받은 돈"과 비교해 차액을 보여 준다. 연도별 최저임금 표로 시급이 최저임금에 못 미치면 경고한다. 받은 금액을 아직 안 넣은 달이 있으면 첫 화면에서 물어본다
3. 단계별 정산 요청: 1단계 사장님께 보낼 정중한 메시지(날짜별 기록과 계산 근거 포함) → 2단계 내용증명 초안 → 3단계 진정 절차 안내(고용노동부 1350 전화, 노동포털 연결). 바로 신고로 가지 않고 대화로 먼저 풀도록 설계했다
4. 증빙 묶음 PDF: 근무 기록, 수정 이력, 계산 근거, 입금 내역, 첨부 사진(근무표·시급 근거·입금 내역), 정산 요청 이력, 기록 등록 확인을 한 문서로 정리한다
5. 기록 등록(서버 타임스탬프): 기록을 남기거나 고칠 때마다 기록 내용으로 만든 확인 번호와 서버 등록 시각이 남는다. 근무지·시각·금액은 서버로 가지 않는다. 누구나 확인 페이지에 확인 번호를 넣어 "그 내용이 그 시각에 있었고 그 뒤 바뀌지 않았다"를 확인할 수 있다

설계 원칙
- 사장 연동 없음. 로그인 없음. 근무 내용은 폰 안에만
- 법적 효력을 보장한다고 말하지 않는다. 근로감독관·법원이 판단할 자료를 정리해 준다. 앱 안의 문서에 그렇게 적어 두었다
- 진정서는 만들지 않는다. 신고 창구로 연결까지만

**2.3 핵심 타겟 고객**
- 주 15시간 이상 일하는 만 19~26세 시급제 아르바이트 대학생. 카페·편의점·음식점. 학업과 병행하며 주 3~5일 근무
- 근로계약서가 없거나 사본이 없고, 입금 총액만 확인하며, 사장에게 정산 문제를 꺼내기 부담스러워한다
- 얼리 어답터: 주휴수당 대상인데 받지 못하고 있거나, 주휴·야간 지급 여부를 모르는 대학생. 곧 그만두거나 최근 그만둔 학생

## 3. SW 기술 요소 및 개발 현황

**3.1 시스템 아키텍처**

기술 스택
| 구분 | 기술 | 선택 이유 |
|---|---|---|
| 프론트엔드 | React 19 + Vite, PWA (서비스 워커로 오프라인 실행, 홈 화면에 추가) | 스토어 심사 없이 링크로 배포. 사용자 의견을 듣고 바로 고쳐 다시 배포할 수 있다 |
| 백엔드 | 별도 서버 없음. Supabase REST API | 근무 내용이 폰 밖으로 나가지 않게. 서버는 확인 번호 등록과 설문 수집에만 쓴다 |
| 데이터베이스 | 폰: localStorage(기록), IndexedDB(사진) / 서버: Supabase PostgreSQL (stamps, survey 표) | 기록 소유권을 사용자에게. 서버 표는 insert·select만 허용하고 update·delete는 막았다(RLS). 등록 시각은 트리거가 서버 시각으로 강제 |
| 인프라 | GitHub Pages + GitHub Actions | main 브랜치에 올리면 자동 빌드·배포 |
| AI | Claude API (선택, 개발 환경에서만) | 배포된 앱은 API 키 없이 정해진 문구로 동작. 기록 내용을 밖으로 보내지 않기 위해 기본은 끔 |
| 분석 | 설문 페이지 + 자동 집계 페이지(Supabase), 직접 인터뷰 | 로그인이 없어 사용 로그 대신 설문·인터뷰로 측정 |

구성도 (그림, 새로 그린다)
- 폰(PWA): 화면(React) ↔ 계산 모듈(급여·비교·문구·PDF·확인 번호) ↔ localStorage·IndexedDB
- 폰 → Supabase stamps 표: 기록 내용의 SHA-256 앞 16자(확인 번호), 기록 번호, 무작위 폰 번호 → 서버가 등록 시각을 찍어 저장
- 확인 페이지(verify.html) → Supabase: 확인 번호로 등록 시각 조회
- 설문 페이지 → Supabase survey 표 → 결과 페이지
- GitHub main → Actions → Pages

데이터 흐름 (기록 하나가 남을 때)
1. 출근 버튼 → 기록 번호 생성 → 출근 시각 기록의 확인 번호를 서버에 등록
2. 퇴근 버튼 → 기록 완성 → 기록 내용의 확인 번호를 서버에 등록
3. 수정 → 수정 이력이 붙은 새 내용의 확인 번호를 다시 등록 (같은 기록에 줄이 여러 개면 그만큼 고쳐진 것)
4. 인터넷이 없으면 대기열에 두었다가 연결되면 보낸다
5. 증빙 묶음 PDF 7번 표에 기록별 확인 번호와 등록 시각이 들어간다

보안·개인정보
- 서버에는 이름, 근무지, 시각, 금액이 가지 않는다. 확인 번호만으로는 내용을 되돌릴 수 없다
- 공개 키만 코드에 있고, 쓰기 권한이 필요한 키는 쓰지 않는다
- 기록 등록은 설정에서 끌 수 있다

## 4. 비즈니스 모델 및 시장성

**4.1 시장 규모와 타이밍**
- 문제의 크기: 임금체불액 2023년 1조 7,845억 원 → 2024년 2조 448억 원 → 2025년 2조 679억 원. 2025년 체불 피해 노동자 26만 2,304명 (고용노동부 노동포털, 임금체불 통계현황)
- 집중되는 곳: 2025년 체불액 중 30인 미만 사업장이 1조 4,012억 원으로 67.8%. 5인 미만 6,130억, 5~29인 7,882억. 카페·편의점·음식점 같은 영세 사업장이 여기에 있다
- 타겟의 경험률: 알바생 48.0%가 임금 관련 문제 경험(알바천국 2025.1), 31.9%가 최저시급 미달 경험(알바천국 2026.6)
- 타겟 규모(어림): 고등교육기관 재적학생 3,072,261명(2026년 교육기본통계, 교육부 2026.8.26 발표. 대학원 포함) × 알바 경험률 약 70~80% → 약 200만 명 안팎이 알바 경험. 대학생 알바 경험률은 학교 단위 조사(동의대 316명 88%, 동국대 200명 67.5%)에서 나온 값이라 전국 대표값이 아니라고 적는다. 그중 주 15시간 이상(주휴수당 대상) 비율은 우리 설문에서 파악한다
- 타이밍: 2025.9 관계부처 합동 임금체불 근절 대책(대지급금 확대), 2025.10.23 개정 근로기준법 시행(상습 체불 사업주 신용 제재 등). 증거만 갖추면 돌려받을 수 있는 길이 넓어졌다
- 2026년 최저임금 10,320원, 2027년 10,700원 고시. 주휴·야간을 포함한 계산은 더 복잡해진다

**4.2 수익 창출 구조**
- 핵심 화면(기록·비교·요청·증빙)은 무료이고 광고를 붙이지 않는다. 신뢰가 핵심인 기능에 광고가 섞이면 안 된다
- 1차(가설): 쉬는 틈 게임 화면에만 광고. 웹앱에서도 Google H5 Games Ads 같은 웹 게임용 광고로 배너·전면·보상형이 가능하다(승인 심사 필요, 아직 신청하지 않음)
- 2차(후보): 여러 폰 동기화, 자동 백업처럼 문서·법률과 무관한 편의 기능의 구독
- 하지 않는 것: 정산 요청 문구, 내용증명 초안, 증빙 묶음의 유료화. 돈을 받고 문서를 만들어 주면 변호사법·공인노무사법 문제에 가까워진다(웹 조사 기준, 전문가 검토 아님)
- 비용: 서버는 Supabase 무료 요금제로 시작, 사용자가 늘면 유료. 인건비는 팀 3명

**4.3 경쟁사 분석 및 차별점**
| 경쟁사 | 하는 것 | 한계 |
|---|---|---|
| 1. 하우머치 | 혼자 근무 기록, 예상 급여 계산, 커뮤니티·매장 후기·돈 관리 | 예상 급여를 보여 주는 데서 멈춘다. 실제 입금액 비교, 체불 대응 없음 |
| 2. 기그 | 출퇴근 기록(GPS), 전자 근로계약서, 급여 계산 | 사장과 연결해야 핵심 기능이 작동. 소규모 매장은 연결이 안 된다는 리뷰 |
| 3. 알바천국·알바몬 계산기 | 시급·시간으로 일회성 계산 | 기록이 남지 않는다 |
| 4. 진정24·고용노동부 노동포털 | 진정서 작성 지원, 진정 접수 | 증거를 이미 갖춘 사람만 쓸 수 있다. 재직 중인 학생에게는 마지막 수단 |

알바가드의 차별점
1. 사장 연동 없이 혼자 쓴다
2. 실제 입금액과 비교해 차액을 찾고, 요청 문구와 증빙 묶음까지 한 흐름으로 잇는다 (네 서비스 모두 없음)
3. 수정 이력 + 기록 등록(확인 번호·등록 시각)으로 "그때 기록한 그대로"를 제3자가 확인할 수 있다 (네 서비스 모두 없음)
4. 바로 신고가 아니라 대화로 먼저 풀도록 단계를 나눴다

약점(솔직하게)
- 비교 기능은 경쟁 앱이 "받은 금액 입력" 칸 하나로 따라올 수 있다. 그래서 기록의 신뢰성을 키우는 쪽으로 간다
- 핵심 기능을 한 달에 한 번 써서 매일 열 이유가 약하다. 쉬는 틈 게임은 이를 보완하려는 시도이고, 광고 자리 후보다
- 확인 번호는 "나중에 고치지 않았다"까지만 보여 주고 "그날 실제로 일했다"는 증명하지 못한다. 통장 내역·메시지와 함께 내야 한다

**4.4 유저 확보 전략**
- 링크 하나로 설치되므로 대학 커뮤니티(에브리타임), 학과·동아리 단톡, 알바 커뮤니티에 링크로 전파
- 주휴수당 계산법 같은 짧은 영상으로 유입
- 지표(앞으로 측정): 홈 화면 추가 → 첫 기록 → 한 달 뒤 받은 금액 입력 → 차액 발견 → 요청 보냄 → (인터뷰로) 실제로 받은 비율

## 5. 남은 과제 및 기말 마일스톤

**5.1 기말 전 추가 개발 계획**
1. 실제 폰 검증: 아이폰·갤럭시에서 기록 등록, PDF 저장, 백업 파일 저장, 사진 첨부, 오프라인 실행
2. 사용자 피드백 반영: 정산 요청 문구 톤, 화면 문구, 입력 흐름
3. 기록 등록 보강: 제3자가 기록 내용으로 확인 번호를 다시 계산해 볼 수 있는 확인 방법
4. 선택: 쉬는 틈 게임 화면 광고 실험(승인되면), 또는 새 게임 "동전 합치기"(퇴근하면 오늘 번 돈이 동전이 되어 쌓이는 방식)
5. 보류 유지: 입금 문자·명세서 사진 자동 인식, 푸시 알림, 로그인

**5.2 시장 검증·피드백 수집 계획**
- 링크 설문(https://jihooni217.github.io/albaguard/survey.html): 지금 알바 중·예전에 함·한 적 없음으로 갈라 20문항 안팎. 11월 중 30명 목표. 결과는 자동 집계 페이지에서 "N명 중 M명"으로 본다
- 직접 인터뷰 5명: 앱을 써 보게 하고 정산 요청 문구를 실제로 보낼 수 있을지, 확인 번호 설명이 이해되는지, 매달 받은 금액을 넣을 만한지
- 지금까지: 타겟 사용자 1명이 디자인 시안을 골랐고(통장 구성), 친구 1명의 스케치로 아이콘을 정했고, 팀원 피드백으로 게임의 "근무 중에만" 조건을 풀었다. [10/27 기준 설문 응답 N명]
