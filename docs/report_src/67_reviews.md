## 검토자 1 · 미니멀리스트

### 1) 한 줄 총평
정하지 못한 것이 화면에 그대로 남아 있고(팀명 후보 4개, "선택" 일정, 2차 수익 후보, "응답 수는 발표 전 갱신"), 정한 것은 두세 번 반복된다(역할 2번, 약점 3번, 법적 안내 문구 3번, 급여 비교 캡처 2번).

### 2) 수정안 (10개, 적용하면 17장 → 16장)
1. 팀명을 하나로. 대상 PPT 1장, 보고서 1.2. 가장 단순한 선택은 앱 이름 "알바가드". 표지 오른쪽을 "팀명 알바가드" 한 줄 + 팀원 세 줄(이름 · 학과 학번 · 역할 한 단어). 보고서 1.2 "팀명은 알바가드이다. 앱 이름과 같다." 후보 나열 삭제. 이유: 완성도 20. 교수님이 동그라미 친 항목을 "미정"으로 보여 주면 바로 깎인다.
2. 2장 삭제, 역할은 한 번만. 2장(역할 분담 표)을 지우고 역할은 표지에 한 단어씩, 자세한 R&R은 17장에 한 번만. 17장 이지훈 첫 줄 "기획 · 개발 · 배포 (지금까지) → 기록 등록 보강, 실제 폰 검증 (앞으로)". 이유: 이지훈 12분에 11장+시연. 한 장 빼면 시연에 1분. 같은 표 두 번은 완성도에 해롭다.
3. 기록 등록 주장을 지금 되는 만큼만. 6장 ③ 설명 → "기록할 때마다 기록 내용으로 만든 확인 번호와 서버 등록 시각이 남는다. 근무지 · 시각 · 금액은 서버로 가지 않는다. 지금은 번호가 언제 등록됐는지까지 누구나 확인할 수 있고, 내용과 맞는지 제3자가 다시 계산하는 방법은 기말까지 만든다." 보고서 2.2 같게. 6장 약점 상자는 두 문장만("비교 기능은 ... 따라올 수 있다. 그래서 다음 단계는 기록의 신뢰성이다."). 이유: 6장(차별점)과 9장(70%)이 다른 말을 하면 기술 타당성에서 질문이 바로 들어온다.
4. 49.3%의 분모. 3장 출처 줄 → "최저시급 미달 경험자 기준 · 알바천국 2026.6 (응답 1,804명)". 이유: 지금은 "1,804명 중 49.3%"로 읽힌다.
5. 캡처 중복 제거, 시연 7단계 → 4단계. 10장은 캘린더 · 증빙 묶음 PDF · 확인 페이지 3장만(급여 비교는 5장과 중복). 11장은 4단계: "1 출근 · 퇴근 버튼 → 설정에서 '2건 등록됨' / 2 첫 화면 '9월 급여 받으셨나요?' → 받은 금액 입력 → 덜 받은 돈 / 3 요청 메시지(3개월 합계) → 증빙 묶음 PDF 7번 '기록 등록 확인' / 4 확인 페이지에 확인 번호 → 서버 등록 시각". 예시 데이터는 발표 전에 미리. 캘린더와 3단계 진정 안내는 말 한 문장으로. "대비" 상자는 노트로. 이유: 3분에 7단계는 넘친다. 네 단계가 차별점과 1:1. "서버를 깨워 둔다"가 화면에 보이면 "서버가 멈추냐"는 질문을 부른다.
6. 구성도는 메시지 하나만. 8장 상자 제목 "Supabase"(무료 요금제 삭제), 맨 아래 배포·설문 줄 삭제. 오른쪽 5단계는 유지. 이유: 구성도 한 장은 "근무 내용은 폰 안에, 서버에는 확인 번호와 등록 시각만" 하나만.
7. 경쟁사 장의 글을 한 문단으로. 13장 오른쪽 첫 문단만 남기고, "전환 비용"(사용자 0명이라 근거 없음)과 셋째(6장과 중복) 삭제.
8. 수익 가설은 하나만, 2차 후보 삭제. 14장·보고서 4.2에서 2차 구독 줄 삭제. 1차 설명 "스도쿠 · 틀린 그림 찾기 · 블록 채우기 화면에만 붙인다. 광고 승인 심사는 아직 신청 전"으로, 광고 상품명·형식 삭제. 이유: "여러 폰 동기화"는 근무 내용을 서버에 올려야 되는데 7·8장이 "근무 내용은 폰 안에만"을 네 번 말한다. 모순.
9. 초기 검증은 사용자 이야기와 숫자만. 15장 들은 것 2줄(타겟 사용자 시안 / 링크 설문 10/23 공개, 10/27 기준 응답 N명. 0이면 "응답 모으는 중"), 계획 2줄. 아이콘·팀원 의견은 시장 검증이 아니므로 삭제. 보고서 5.2 대괄호 자리표시 제거.
10. 간트에서 "선택" 삭제(5줄로), 보고서 5.1 4번은 "기말 이후: 게임 화면 광고 승인 신청" 한 줄. 17장 손유호 라벨 "시장 · 수익", 둘째 줄 "비즈니스 모델, 설문 집계". 17장 "법적 효력 ..." 줄 삭제(6장과 부록 C에 있음). 이유: 7주에 개발자 1명. "선택"이 붙은 줄은 안 할 일. 같은 안내 문구 세 번은 불안으로 읽힌다.

### 3) 예상 질문
Q1 "확인 번호를 저장하는 서버가 멈추거나 없어지면? 무료 서버 아닌가?" → 기록 내용과 수정 이력은 폰에, 확인 번호와 등록 시각은 증빙 묶음 PDF 7번 표에 인쇄돼 사용자 손에 남는다. 서버는 제3자가 다시 확인하는 용도. 무료 요금제라 일주일 요청 없으면 멈추지만 데이터는 안 지워지고, 멈춘 동안의 기록은 대기열에 있다가 보내진다. 사용자가 생기면 유료로.
Q2 "광고로 얼마나? 서버 비용은?" → 숫자는 아직 없다. 운영 비용 0원이라 수익 0이어도 돌아간다. 사용자가 생긴 뒤 승인 신청해 단가를 잰다. 문서 유료화는 법적 이유로 안 한다.

### 3) 예상 질문
Q1 "서버는 여러분이 관리하는데 등록 시각을 고칠 수 있지 않나? 제3자가 왜 믿나?" → 공개 키로는 넣기·읽기만, 시각은 서버가 찍는다. 다만 프로젝트 소유자는 관리 화면에서 고칠 수 있다. 한계로 인정. 지금 보여 주는 건 "사용자가 나중에 고칠 수 없다"까지. 외부 기관 시점 확인은 비용 때문에 계획. 증빙 묶음에 등록 시각과 번호를 같이 찍어 서버와 대조할 수 있게 했다.
Q2 "앱이 알바생 쪽으로 계산하면 사장이 틀렸다고 하지 않나? 책임은?" → 계산을 단정으로 내놓지 않고 항목별·주별 이유를 펼쳐 보여 준다. 해석이 갈리는 부분(합의 휴무, 연장근로 미반영)은 화면에 적었다. 요청 문구도 확인 요청 톤. 법률 자문 아님을 적어 두었고 1350 안내. 판단은 감독관·법원.

### 4) 이것만은 꼭

## 검토자 3 · 제1원칙

### 1) 한 줄 총평

### 2) 수정안
1. 팀명을 정해서 적는다. 못 정하면 "알바가드". 보고서 1.2 "팀명: ○○○" 한 줄.

### 3) 예상 질문

## 검토자 4 · 선행 사례

### 1) 한 줄 총평
주장은 많은데 증거의 모양이 약하다. 구현 비율은 팀이 어림한 % 막대뿐이고, 검증 계획은 가설도 합격 기준도 없이 인원수만 있다. 잘 된 피치와 캡스톤 우수작은 둘 다 "확인할 수 있는 표"로 보여 준다.

### 2) 수정안
1. 팀명을 "알바가드"로(YC 피치: 팀 이름 = 제품 이름). "후보"라는 말은 어디에도 남기지 않는다.
2. 기존 대안 표에 "메모 · 카톡(나에게 보내기)" 열을 넣고 ✓/✗ 표로(YC "substitutes", Sequoia "alternatives"). 5행(사장 없이 혼자 기록 / 예상 급여 계산 / 실제 입금액과 비교 / 요청 문구·증빙 묶음 / 수정 이력·등록 시각) × 6열(메모·카톡 / 하우머치 / 기그 / 계산기 / 진정24 / 알바가드). 메모·카톡은 혼자 기록 ✓, 수정 이력 △(보낸 시각만). 표 아래 "신고 창구가 없어서 덮이는 게 아니다. 말을 꺼낼 근거와 시점이 없어서 덮인다. 알바가드는 그 앞 단계를 채운다." 5장 세 칸 위 꼬리표 "문제 1·2 → 비교, 문제 3 → 요청, 기록은 셋의 바탕". 이유: 무료 앱의 진짜 경쟁자는 "메모장과 통장 확인".
3. 9장 % 옆에 "동작(컴퓨터) / 폰 확인 / 사용자 확인" ●○ 세 칸(요구사항 추적표·완료 정의). 지금은 8줄 모두 ● ○ ○. 설명 "% = 기능 범위 중 만든 비율(팀 어림). 폰·사용자 확인은 %에 넣지 않고 따로 표시." 아래 "계획에서 바뀐 것": 더한 것(기록 등록·백업·증빙 사진·퇴직금 알림) / 뺀 것(푸시 알림·금액 자동 인식) / 바꾼 것(게임 조건 10/25).
4. 보고서 3.2 끝에 "검증 현황(2026.10.25 기준)" 표: 확인 항목 × (컴퓨터 Chrome / 아이폰 Safari / 갤럭시 / 비고). 설치(아이폰 확인 10/7, 갤럭시 미확인) / 기록 등록(컴퓨터 확인, 폰 미확인) / 오프라인·PDF·백업·사진(미확인) / 너비 320·375·430(컴퓨터 확인) / 어두운 화면(10/6) / 게임 조작 크기 / 서버 시각 강제(확인) / 수정·삭제 거부(401 확인) / 무료 잠듦(10/23 확인). 이유: "동작한다" 문장 여덟 개보다 확인/미확인 표 하나. 미확인 칸이 5.1·5.3 일정과 1:1.
5. 8장 Supabase 상자 아래 "확인함: 2000년 시각을 보내도 서버 시각으로 저장됨 / 수정·삭제 요청은 거부됨(401)". 멘트 "걸어 놓고 뚫어 봤습니다."

8. 간트에 ◆ 마일스톤·산출물 5개, 위에 "지난 3주(10/5~10/25) 한 일" 띠(시안 12장 → 통장 구성 / 10/7 아이콘·아이폰 설치 / 10/13 기록 등록·MVP 정의서 / 10/23 설문 공개 / 10/25 게임 조건 변경 / 커밋 146건), 보고서 5.1 끝 리스크 3줄(서버 잠듦 / 설문 30명 미달 → 사람 수로·인터뷰 비중 / 일정 밀림 → 선택 작업 먼저 뺀다).

10. 마지막 장을 "여쭙고 싶은 것 두 가지"로(YC 오피스아워 "the ask"): ① 수익 모델: 게임 화면 광고 말고, 문서 유료화를 피하면서 가능한 모델이 있을까요? ② 검증: 설문 30명·인터뷰 5명이면 충분한지, 더 봐야 할 지표가 있을까요? 법적 효력 줄은 줄이거나 뺀다.

### 3) 예상 질문
Q1 "서버는 여러분이 관리한다. 고치면 그만 아닌가?" → 맞다. 공개 키로는 넣기만 되는 것까지 확인했지만 소유자 권한으로는 고칠 수 있다. 지금 막는 건 "사용자 본인이 나중에 고쳐 쓰기"까지. 외부 공인 타임스탬프는 비용 때문에 계획. 서버에는 번호만 있어 운영자가 서버를 고쳐도 폰의 근무 내용 자체는 못 바꾼다.

### 4) 이것만은 꼭

## 검토자 5 · 적대적

### 1) 한 줄 총평
